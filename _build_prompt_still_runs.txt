THE RULE (also in SCORING.md - implement exactly this, do not invent a
different scoring shape):

For a given instance:
  1. OLD run: run the project's own test command (whatever run_test.sh
     specifies, via test_command() from build_instances.py) using the Python
     already provisioned inside the instance (instance_dir/.python/python.exe).
     Run it directly against the instance folder - read only, no copy needed.
     Record: did it collect/run at all, and how many tests failed.
  2. NEW run: copy the instance to a scratch folder (NOT under instances/ -
     put scratch work under a new top-level "portability_scratch/" folder,
     which must be added to .gitignore, same as fixes/ and instances/ are).
     Exclude .python, .git, __pycache__, .pytest_cache, .ruff_cache when
     copying (shutil.ignore_patterns, same list fix_bug.py uses plus .python).
     In the scratch copy, create a plain venv using THIS machine's own current
     Python (sys.executable, `python -m venv`) - do not use
     build_instances.provision_python for this, a plain venv of the current
     interpreter is the "current Python" side of the comparison.
     Reinstall the same declared dependencies into that venv: the bug's
     requirements.txt, the same testing-extras list build_instances.py
     installs (pytest, ruff, pytest-mock, pytest-cov, freezegun, mock,
     pytest-timeout, nose, parameterized, pytest-asyncio), any of
     requirements-dev.txt / test_requirements.txt / requirements/test.txt /
     dev-requirements.txt that exist, then `pip install -e .`.
     Run the identical test command in the venv. Record the same two signals.
     Delete the scratch copy when done - it is disposable, never commit it.
  3. Compare the two runs and produce ONE of three verdicts:
     - PORTABLE: the NEW run collected/ran, and its failed-test count is
       <= the OLD run's failed-test count. Nothing that worked before broke.
     - BROKEN: the NEW run could not even collect/start (e.g. an import the
       project relies on no longer exists on current Python), OR its failed
       count is greater than the OLD run's. Record the concrete error line
       from the NEW run as the evidence (reuse first_error() from
       build_instances.py for this).
     - NOT_APPLICABLE: the OLD run itself could not collect/run at all. There
       is no usable baseline, so make no claim either way - this is not the
       same as PORTABLE and must never be silently folded into it.

  Parsing test output: handle BOTH pytest summary lines ("3 failed, 180
  passed in 12s" / "180 passed in 4s") AND unittest summary lines ("OK" /
  "FAILED (failures=3)" / "FAILED (errors=2)"), since test_command() can
  return either runner depending on the project (see its docstring - black,
  tornado and youtube-dl use unittest with dotted module paths). A run that
  could not be collected at all shows up as ModuleNotFoundError, ImportError,
  SyntaxError, "collected 0 items", "no tests ran", or "found no collectors"
  in the output - treat any of those as collection failure, not as "0 failed".
