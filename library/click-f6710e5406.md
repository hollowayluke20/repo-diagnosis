## Problem

Byte-valued command-line arguments were not decoded with the UTF-8 fallback when the filesystem encoding matched the argument encoding. In that case, the conversion path was skipped entirely, leaving bytes unconverted instead of producing text, particularly for input that needed UTF-8 decoding or replacement of invalid sequences.

## Fix shape

Ensure the UTF-8-with-replacement fallback runs whenever the primary filesystem-based decoding path is not applicable, including when the two detected encodings are equal.
