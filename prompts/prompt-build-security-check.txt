THE GOAL - THIS IS ACTUALLY TWO SEPARATE CHECKS

1. KNOWN HOLES IN LIBRARIES. A project declares the libraries it depends on
   (requirements.txt, setup.py, pyproject.toml, etc). For each one, check
   whether that exact library and version has a publicly recorded security
   problem. This is a lookup against a public advisory database, not
   judgement - no AI needed. A hit must name the exact library, the exact
   version, and the specific advisory it matches. Never claim "this repo is
   at risk" - only ever claim "this repo uses a version with a recorded
   advisory attached to it." Whether the vulnerable part is actually reachable
   the way this project uses it is a separate, harder claim we are not making.

2. EXPOSED SECRETS IN THE CODE ITSELF. Search the actual text of the
   repository for things that match the SHAPE of a real API key, password, or
   token - not a lookup, a pattern search. A hit must quote the exact file and
   line.

   This one is dangerous to get wrong in a specific way: a false alarm here
   reads as "you have leaked a credential", which is a much scarier claim than
   "your dependency is old." Test fixtures are full of fake example keys
   ("your-api-key-here", variables literally named example_password) that
   LOOK like real secrets and are not. Do not let this check cry wolf.

THE TEST PLAN - already agreed, follow it exactly

  1. Build the check.
  2. Add a CONTROL case before testing on real projects: run it against a
     project you are confident has NO known holes and NO real secrets in it.
     It must stay quiet. If it invents a finding on clean code, that is the
     first thing to fix, before anything else.
  3. Test on 10 real instances from instances/ (do not touch the locked pile -
     see MANIFEST.md).
  4. Look at what it found, reconfigure whatever needs it.
  5. Test on 10 DIFFERENT instances it has not seen. Reusing the same ten
     teaches the ten, not the check.
  6. Reconfigure again if needed, then test on 20.

Report actual findings from real runs at each step, not descriptions of what
you expect to find.
